# GSTU diploma and report rules

This summary is based on the local methodical guide `4334 (1).pdf`: `Дипломное проектирование : учеб.-метод. пособие` for GSTU specialties `1-40 04 01` and `1-40 05 01`, Gomel, 2019. It is a diploma-work guide, so the formatting rules below are used as the working GSTU ruleset for diploma works and as the default formatting basis for similar academic reports unless the user provides a narrower document-specific guide.

## Standards explicitly cited in the guide

- `ГОСТ 7.32-2001` - report structure and general research-report basis.
- `ГОСТ 7.1-2003` - bibliographic description and source list formatting.
- `СТБ 6.38-2004` - cited by the guide as a normative basis.
- `ГОСТ 2.105-95` - general requirements for text documents.
- `ГОСТ 8.417-2002` - units of physical quantities.
- `ГОСТ 2.316-2008` - accepted abbreviations.
- `ГОСТ 19.401-78` - program text formatting.
- `ГОСТ 19.503-79` - system programmer manual.
- `ГОСТ 19.504-79` - programmer manual.
- `ГОСТ 19.505-79` - operator or user manual.
- `РД 50-34.698-90` - recommended basis for user guide structure.

## Diploma topic rules

- The topic should be one sentence and reasonably short.
- The topic must match the university order exactly once approved.
- Do not use punctuation marks such as commas, colons, or brackets in the topic.
- Prefer a topic that starts with the developed system or product type: `система`, `подсистема`, `автоматизированная система`, `программа`, `программный комплекс`, `программный модуль`, `веб-узел`, and similar.
- Do not use `метод`, `алгоритм`, `модель` and similar items as the development object.
- Do not start the topic with `разработка`, `проектирование`, `решение задачи`, and similar wording.
- The topic should clearly state the purpose of the developed information system or software.
- Do not include foreign-language words or abbreviations unless they are part of an organization name.
- Do not include programming languages, DBMS names, corporate systems, design technologies, mathematical methods, or similar implementation tools in the topic.

## Required diploma deliverables

- Before defense, the student provides the secretary of the State Examination Commission with the bound explanatory note, supervisor review, review by a reviewer, printed signed presentation slides, printed report text, supporting materials such as implementation acts or publications, an originality report from an anti-plagiarism system, and an electronic medium.
- The electronic medium should contain the explanatory note, working program, electronic abstract and resume, multimedia presentation and report, and electronic versions of supporting materials.
- Supervisor review, reviewer review, implementation acts, publication list, and other value-confirming materials are attached separately and are not bound into the explanatory note.
- The defense presentation should contain at least `15` slides.
- The defense report and software demonstration are given within up to `15` minutes; the full defense is allocated up to `30` minutes.

## Diploma explanatory note structure

Use this order for diploma work unless a department template overrides it:

1. Title page.
2. Abstract.
3. Diploma assignment.
4. Resume in Russian, Belarusian, and a foreign language, preferably English.
5. Contents.
6. List of symbols and abbreviations, if needed.
7. Introduction.
8. Section 1: task description, analytical review of existing methods and tools, analogues, advantages and disadvantages of known solutions, and requirements/technical assignment.
9. Section 2: software architecture, domain model, functional requirements, data model, database structure if needed, and internal/external interfaces.
10. Section 3: software structure, main algorithms, implementation, user interface, reachability tree of main functions, input and output formats.
11. Section 4: testing, verification, validation, trial operation, computational experiment, and analysis of results.
12. Section 5: economic justification.
13. Section 6: occupational safety.
14. Section 7: resource and energy saving.
15. Conclusion.
16. List of used sources.
17. Appendices.

Approximate diploma volumes:

- Explanatory note without appendices: at least `75-85` sheets.
- Introduction: `1-3` pages.
- Section 1: `12-15` sheets.
- Section 2: `10-12` sheets.
- Section 3: `10-12` sheets.
- Section 4: `10-12` sheets.
- Section 5: `5-7` sheets.
- Section 6: `3-5` sheets.
- Section 7: `3-5` sheets.
- Conclusion: `1-2` pages.

## Front matter rules

- Title page: department and faculty names are written without abbreviations; the topic is written in uppercase and must match the approved title; the title page counts in total pagination but has no visible page number.
- Abstract: includes work volume, number of illustrations, tables, appendices, sources, `5-10` keywords, object, purpose, method, results and novelty, application area, implementation results or practical-use proposals.
- Abstract length: not more than `1` page; recommended text length is `1000-1200` characters.
- Abstract must include the required originality statement that the diploma work was completed independently, checked in the named anti-plagiarism system, with originality percentage stated, and that citations are linked to sources in the source list.
- Assignment: issued by the supervisor, signed by supervisor and student, approved by department head, bound into the diploma work, counts as one sheet, and has no visible page number.
- Resume: prepared in Russian, Belarusian, and a foreign language, preferably English; includes topic, object and research tools, main independently obtained conclusions; total length for all three languages is not more than `1` page.
- Contents: includes introduction, abbreviations list if present, sections, subsections, conclusion, source list, and appendices with starting page numbers.
- First content sheet has no visible page number. Visible numbering starts from the second content sheet, or from the abbreviations list, or from the introduction if earlier elements fit on one sheet.
- List of symbols and abbreviations starts with wording like `В настоящей пояснительной записке применяются следующие термины, обозначения и сокращения...`.
- In the abbreviations list, place terms in a left column and explanations to the right. Put Russian terms first in alphabetical order, then English terms in alphabetical order, then terms in other languages.

## Page layout and basic text formatting

- Paper format: `A4`, one-sided printing.
- Margins: top `20 mm`, bottom `20 mm`, left `30 mm`, right `10 mm`.
- Font: `Times New Roman`, `14 pt`.
- Line spacing: about `40 +/- 3` lines per page; in Word the guide recommends single spacing or multiplier `1.1`.
- Alignment: justified.
- Automatic hyphenation: allowed in body text, not in headings.
- First-line indent: `1.25 cm`.
- Font color: black, uniform through the whole document.
- Emphasis: italic, bold, bold italic, and underline are allowed for definitions, terms, theorems, and important features.
- Latin symbols in text: italic.
- Distinguish dashes and hyphens: hyphen `-` has no surrounding spaces, while dash `-`/`–` is separated by spaces on both sides in Russian explanatory text.
- Corrections in printed text may be made with correction fluid and corrected text in the same place.

## Pagination

- Page numbers use Arabic numerals.
- Number position: bottom right.
- Font for page number: `Times New Roman`, `12 pt`.
- Title page counts as page 1 but is not numbered.
- Abstract, assignment, resume, and the first content sheet are included in total count but not numbered visibly.
- Visible numbering starts from the second content sheet, or from the abbreviations list, or from the introduction if earlier elements fit on one sheet.
- Appendices are included in the common pagination.

## Headings and section numbering

- Main text is divided into sections, subsections, and points.
- Sections: Arabic numerals, no trailing dot, from paragraph indent.
- Subsections: `section.subsection`, no trailing dot.
- Points: `section.subsection.point`.
- Sections and subsections must have headings; points usually do not.
- Section headings: uppercase letters, bold, from paragraph indent.
- Subsection headings: sentence case, bold, from paragraph indent.
- Point numbers: bold italic.
- No underline in headings.
- No period at the end of headings.
- No hyphenation inside headings.
- If a heading has two sentences, separate them with a period.
- If a heading wraps to several lines, align following lines with the first letter of the first line.
- Every section starts on a new page.
- Keep at least some body text with a subsection heading on the same page.
- Do not move the last line of a section or subsection to a separate page.
- Separate section/subsection headings and text with a blank line.
- If a section is divided into subsections, do not leave text outside subsections.
- A subsection should be at least about one page and should not contain only figures, tables, or formulas without explanatory text.
- Sections and subsections start with text.
- Center these unnumbered headings: `Перечень условных обозначений и сокращений`, `Реферат`, `Список использованных источников`, with sentence case and bold.
- Use uppercase bold centered headings for `СОДЕРЖАНИЕ`, `ВВЕДЕНИЕ`, and `ЗАКЛЮЧЕНИЕ`.

## Lists

- For an unnumbered list made of separate phrases or paragraphs, each item starts from paragraph indent with a dash, starts with a lowercase letter, and ends with a semicolon except the final item.
- If the text needs to refer to a list item, use lowercase Russian or Latin letters followed by a closing parenthesis: `а)`, `б)`, `в)`.
- For deeper detail inside lettered lists, use Arabic numerals followed by a closing parenthesis.
- A list item should not contain several independent sentences separated by periods; move those sentences to normal paragraphs where possible.
- When referring to a list item in text, omit the closing parenthesis and write `пункт` without abbreviation, for example `в пункте б`.
- When referring to a detailed item, write the detail through a dot, for example `в пункте б.3`.

## Academic style and wording

- Use scientific and technical terminology established by standards or accepted literature.
- Do not use colloquialisms, professional slang, arbitrary word formation, or interchangeable synonyms for the same concept.
- Do not shorten words except by accepted standard rules.
- Use standardized units per `ГОСТ 8.417-2002`.
- Write numbers with units in digits.
- Write numbers from one to nine in words when no unit follows.
- In requirements, use forms like `должен`, `следует`, `необходимо`, `не допускается`.
- Do not use foreign words and terms where an equivalent Russian term exists.
- Do not use a mathematical minus sign before negative values in running text; write the word `минус`.
- Do not use the diameter sign in running text; write the word `диаметр`.
- Do not use mathematical signs or signs `номер` and `процент` without numeric values.
- Do not cite standards, technical specifications, or other documents by index without a registration number.
- Explain non-standard symbols at first mention or in the list of symbols and abbreviations.

## Contents

- Contents must include introduction, abbreviations list if present, section and subsection titles, conclusion, source list, and appendices.
- Entries align vertically.
- Subsection entries are indented by one paragraph indent relative to sections.
- Dot leaders run to the page number.
- Page numbers align vertically so the last digit is consistently positioned near the right edge.
- If a contents entry wraps and any line would move to the next page, move the whole entry.
- Appendix entries include the appendix letter and its title.

## Figures

- Place a figure immediately after the first textual reference or on the next page.
- All figures must be referenced in text.
- Number figures within each section: `Рисунок 3.4`.
- Caption is centered under the figure.
- Caption and figure are separated by a blank line.
- Figures may be placed in text or on separate sheets. A separate-sheet figure goes after the page where it is first referenced.
- Figures may be rotated `90` degrees counterclockwise on the long side of the sheet.
- Use uniform illustration style, notation, labels, dimension lines, and callouts throughout the document.
- Figures should be created with a graphical editor; color is allowed.
- Minor inline illustrations that are not referenced later may remain unnumbered.
- If a caption or figure name uses several lines, center each following line relative to the previous line.
- Explanatory data may be included in the figure caption, separated by semicolons, using dashes such as `а - подсистема; б - таблица БД`.
- If a figure continues on later pages, keep the title on the first page and mark later sheets accordingly.
- In appendices use numbering like `Рисунок А.2`.

## Formulas

- The guide recommends `Equation 3.0`, but any editor is acceptable if the visual rules match.
- Latin variables: italic.
- Greek symbols: upright.
- Formulas are separated from text by blank lines.
- Explain symbols directly under the formula.
- The first explanation line starts with `где` and no colon.
- Explain symbols in the order in which they appear in the formula, each from a new line.
- A formula may be broken only at operation signs, and the sign repeats at the start of the next line.
- When breaking at multiplication, use `×`.
- Do not break at division signs or inside expressions belonging to root, integral, logarithm, trigonometric functions, and similar operators.
- Number formulas within each section: `(3.1)`.
- Put the number at the right margin.
- If a section has one formula, number it anyway, for example `(1.1)`.
- For one-line formulas, put the number on the same line; for multiline formulas, put the number on the last line; for a complex fraction, align the number with the fraction bar center.
- All formulas must be referenced in text explicitly with a word such as `формула`, `уравнение`, `выражение`, `равенство`, or `передаточная функция`, for example `по формуле (2.1)`.
- Short similar formulas may be placed on one line and separated by semicolons.
- Simple short intermediate formulas may be placed inline if spacing remains readable.

## Tables

- Place a table after the first textual reference or on the next page.
- All tables must be referenced in text.
- Table title goes above the table, left aligned from paragraph indent.
- Number tables within each section: `Таблица 4.2`.
- Titles should be concise and informative.
- Text above and below the table is separated by a blank line.
- Column headings use capital letters; subheadings use lowercase if they continue the heading meaning.
- No period in headings or subheadings.
- Headings and subheadings use singular form and are centered.
- The `No.` column should not be added as a default column.
- On continuation pages use `Продолжение таблицы ...` or an equivalent automated continuation style.
- In appendices use numbering like `Таблица В.1`.
- Tables are aligned to the left edge of the main text.
- If a section has one table, number it anyway, for example `Таблица 1.1`.
- Tables are usually bordered on the left, right, and bottom.
- Do not separate table headings and side headings with diagonal lines.
- Internal horizontal and vertical lines may be omitted if readability is not impaired.
- Table header must be separated by a line from the rest of the table.
- Row height should be at least `8 mm`.
- Table may be rotated along the long side of the sheet.
- Number columns with Arabic numerals only when referenced in text, when splitting a table into parts, or when continuing a table on another page.
- If common to all values in a row, a unit is written after the row name, separated by a comma.
- Numeric values should align by digit place in a column, with the same number of decimal places where possible.

## Source list and in-text citations

- Source list title: `Список использованных источников`.
- Place it before appendices.
- Preferred ordering: by first appearance in the text.
- Alternative allowed: alphabetical order.
- Use Arabic numerals with a period and paragraph indent.
- Include only sources that are actually cited.
- In-text citations use square brackets, for example `[1]`.
- For large sources, page or figure уточнение is allowed, for example `[1, с. 386]`.
- Internet sources should be official resources of organizations, authorities, or official language or technology references where possible.
- Bibliographic formatting follows `ГОСТ 7.1-2003`.
- The same source is listed only once.
- A source may be cited in text at first mention; do not include unused sources.
- Bibliographic description areas are separated by `. -`.
- Put one space after prescribed punctuation.
- Do not put spaces before a period or comma, before a colon that is part of the main title, or between author initials.
- Put spaces before a dash, slash, double slash, semicolon, and a colon that separates bibliographic-description areas.
- Each new bibliographic-description area starts with a capital letter, and the description ends with a period.
- For one to three authors, record the first author at the beginning and list authors after the slash. For four or more authors, use the title at the beginning and list the first author plus `[и др.]` after the slash.
- In output data, abbreviate `Москва`, `Санкт-Петербург`, and `Ростов-на-Дону` as `М.`, `СПб.`, and `Ростов н/Д`; write other cities fully.
- Do not write the word `год` or letter `г` after the publication year.

## Appendices

- Appendices may be mandatory, recommended, or reference.
- Every appendix starts on a new page.
- Top center: `ПРИЛОЖЕНИЕ` plus its letter.
- Next line in parentheses: `обязательное`, `рекомендуемое`, or `справочное`.
- Next line: appendix title, centered.
- Appendices are ordered by first reference in the text.
- Every appendix must be referenced in the main text.
- Allowed appendix letters: Russian capital letters starting from `А`, excluding `Е`, `З`, `Й`, `О`, `Ч`, `Ъ`, `Ы`, `Ь`.
- Reduced font `10-12 pt` is allowed inside appendices if readability remains acceptable.
- Numbering of figures, tables, and formulas in appendices replaces the section number with the appendix letter.

## Program text and software documents

- Program code should be placed in appendices, not in the main text.
- Program text follows `ГОСТ 19.401-78` and should include comments sufficient for a specialist to understand the program's purpose and structure.
- Follow the standard code conventions of the programming language.
- For code appendices the guide allows `Times` `10-12 pt`, single spacing.
- Small code fragments up to about half a page may appear in the main text as figures if they are needed for explanation.
- Functionally independent program components may be placed in separate appendices or separate parts of one appendix.
- If the report includes separate manuals, the guide points to:
  - `ГОСТ 19.503-79` for the system programmer manual;
  - `ГОСТ 19.504-79` for the programmer manual;
  - `ГОСТ 19.505-79` and `РД 50-34.698-90` for the user manual.

## Required software-document appendices for diploma work

The guide expects these software documents in appendices when applicable:

- System programmer manual: general information, program structure, setup, program check, additional capabilities if justified, messages to the system programmer.
- Programmer manual: purpose and conditions of use, program characteristics, program invocation, input and output data, messages.
- User manual: introduction, purpose and conditions of use, preparation for work, operation description, emergency situations, learning recommendations.

## Multimedia presentation

The presentation should contain at least `15` slides and cover:

- task statement and research goals;
- information model of the researched system;
- software functional diagram;
- data schema;
- database schema;
- main algorithms, preferably graphical algorithm schemes;
- input data description;
- program results;
- result analysis;
- conclusions.

## Safe adaptation for GSTU reports

Use the formatting rules above directly. For structure, adapt them to the requested document type. For a report, this default structure is safe:

1. Title page.
2. Assignment or individual task, if required.
3. Contents.
4. Abbreviations, if needed.
5. Introduction.
6. Description of the organization or project context.
7. Analysis of the subject area and tools.
8. Description of completed work.
9. Results and evaluation.
10. Conclusion.
11. Source list.
12. Appendices.
